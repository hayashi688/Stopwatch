# 作業時間記録アプリ 要件定義書

**バージョン：1.0**

## 第1章 アプリケーション概要

### 1.1 目的

日々の作業時間を記録し、作業項目やグループごとに費やした時間を管理・可視化するWebアプリケーションを開発する。

作業時間の記録には、以下の2つの方法を用意する。

1. ストップウォッチによる時間計測
2. ユーザーによる作業時間の手動入力

### 1.2 想定利用者

- 個人利用を想定する。
- 主にPCのWebブラウザから使用する。
- スマートフォンからの操作にも対応する。
- 初期バージョンではログイン機能を設けない。

### 1.3 基本方針

- 作業項目を自由に登録できる。
- 作業項目をグループで分類できる。
- 作業項目を選択してストップウォッチで時間を計測できる。
- 計測中の時間をキャンセルして破棄できる。
- ユーザーが作業時間を直接入力して登録できる。
- 作業時間はPostgreSQLに永続化する。
- 日別の作業時間を作業項目別・グループ別に集計できる。
- 過去の作業記録を確認・編集・削除できる。

## 第2章 画面要件

### 2.1 画面構成

メイン画面は以下の5つのエリアから構成する。

1. ストップウォッチエリア
2. 作業項目管理エリア
3. 手動作業時間登録エリア
4. 作業時間集計エリア
5. 作業記録履歴エリア

基本的な操作は1画面で完結させる。

### 2.2 ストップウォッチエリア

**表示項目**

- 選択中の作業項目名
- 現在の計測時間（HH:MM:SS）
- 計測状態（未開始・計測中）
- スタートボタン
- ストップボタン
- キャンセルボタン

**操作**

- スタート：時間計測を開始する。
- ストップ：計測を終了し、作業時間を保存する。
- キャンセル：計測を終了し、計測時間を保存せず破棄する。

キャンセル時には確認ダイアログを表示する。

### 2.3 作業項目管理エリア

**表示項目**

- グループ登録欄
- グループ選択欄
- 作業項目名入力欄
- 作業項目追加ボタン
- グループ別作業項目一覧
- 各作業項目の本日累計時間

作業項目一覧から、ストップウォッチの計測対象を1つ選択できる。

### 2.4 手動作業時間登録エリア

**入力項目**

| 項目 | 必須 | 内容 |
|---|---|---|
| 作業日 | ○ | 作業した日付 |
| グループ | - | 作業項目の絞り込み |
| 作業項目 | ○ | 登録対象の作業 |
| 時間 | ○ | 作業時間（時） |
| 分 | ○ | 作業時間（分） |
| メモ | - | 作業内容の補足 |

時間・分はそれぞれ数値入力とし、時間は0以上、分は0〜59とする。両方0の場合は登録できない。

**操作**

- 登録ボタンを押すと入力時間を作業記録として保存する。
- 登録成功後、集計エリアと履歴エリアを更新する。
- 入力エラーがある場合は保存せず、エラー内容を表示する。

### 2.5 作業時間集計エリア

**表示項目**

- 集計対象日
- 前日・翌日への切り替え
- カレンダーによる日付選択
- その日の合計作業時間
- グループ別合計時間
- 作業項目別合計時間

デフォルトでは当日を表示する。

### 2.6 作業記録履歴エリア

**表示項目**

- 作業日
- グループ名
- 作業項目名
- 記録方法（ストップウォッチ／手動）
- 作業時間
- 開始・終了時刻（ストップウォッチ記録のみ）
- メモ
- 編集ボタン
- 削除ボタン

## 第3章 作業グループ管理機能

### F-01 グループ登録

1. グループ名を入力して登録できる。
2. グループ名は必須とする。
3. 空文字・空白のみの登録は禁止する。
4. 同一名称のグループの重複登録は禁止する。
5. 登録結果はDBに保存する。

### F-02 グループ一覧表示

1. 登録されたグループを一覧表示する。
2. グループごとに所属する作業項目をまとめて表示する。
3. グループ未設定の作業項目は「未分類」に表示する。

### F-03 グループ編集・削除

1. グループ名を変更できる。
2. グループを削除できる。
3. 削除対象グループに所属する作業項目は削除せず、「未分類」に変更する。
4. 過去の作業時間記録は削除しない。

## 第4章 作業項目管理機能

### F-04 作業項目登録

1. 作業項目名を入力して登録できる。
2. 作業項目にはグループを設定できる。
3. グループ未設定でも登録できる。
4. 空文字・空白のみの項目名は登録できない。
5. 同一グループ内での作業項目名の重複は不可とする。
6. 登録内容はDBに保存する。

### F-05 作業項目一覧・選択

1. 登録された作業項目をグループ別に一覧表示する。
2. 作業項目をクリックすると選択状態になる。
3. 同時に選択できる作業項目は1つのみとする。
4. 選択中の作業項目を視覚的に区別する。
5. 作業項目ごとの当日累計時間を表示する。

### F-06 作業項目編集・アーカイブ

1. 作業項目名を変更できる。
2. 所属グループを変更できる。
3. 作業項目をアーカイブできる。
4. アーカイブした項目は通常の選択一覧から除外する。
5. 過去の作業記録は保持する。
6. 計測中の作業項目はアーカイブできない。

## 第5章 ストップウォッチ機能

### F-07 計測開始

**前提条件**

- 作業項目が選択されていること。
- 他の計測が実行されていないこと。

**処理**

1. ユーザーがスタートボタンを押す。
2. Spring Bootの計測開始APIを呼び出す。
3. サーバーで現在日時を取得する。
4. 計測セッションをDBに保存する。
5. JavaScriptで経過時間の表示を開始する。
6. 計測状態を「計測中」に変更する。

### F-08 計測停止

**処理**

1. ユーザーがストップボタンを押す。
2. 計測停止APIを呼び出す。
3. サーバーで計測終了日時を取得する。
4. 開始日時との差から経過時間を計算する。
5. 作業記録をDBへ保存する。
6. 計測セッションを終了する。
7. 計測状態を「未開始」に変更する。
8. ストップウォッチの表示を00:00:00に戻す。
9. 日別集計・作業項目一覧・履歴を更新する。

### F-09 計測キャンセル

**目的**

ストップボタンを押し忘れた場合や、誤って計測を開始した場合に、不要な作業時間が記録されることを防止する。

**処理**

1. 計測中にキャンセルボタンを押す。
2. 「計測中の時間を破棄しますか？」という確認ダイアログを表示する。
3. 確認ダイアログで「キャンセルしない」を選択した場合、計測を継続する。
4. 「破棄する」を選択した場合、計測キャンセルAPIを呼び出す。
5. サーバーで計測セッションを終了し、状態をCANCELEDに変更する。
6. 作業記録は作成しない。
7. ストップウォッチを00:00:00に戻す。
8. 計測状態を「未開始」に変更する。

**制約**

- キャンセルした時間は日別集計に含めない。
- キャンセルした時間は作業記録履歴に表示しない。
- キャンセル後の計測再開はできない。再度スタートする。
- キャンセル処理が失敗した場合は計測状態を保持し、エラーを表示する。

### F-10 計測状態復元

1. 計測中にページを再読み込みしても計測を継続する。
2. ブラウザを閉じても、計測状態をDBに保持する。
3. 再度ページを開いた際、計測状態取得APIを呼び出す。
4. 計測中セッションがある場合、開始日時から経過時間を復元する。
5. 復元後もストップ・キャンセル操作を利用できる。
6. ブラウザを閉じただけでは作業記録を確定保存しない。
7. 計測時間が長時間経過していても自動保存しない。

**停止忘れ時の仕様**

計測が長時間継続した場合でも、自動的に作業実績として登録しない。

ユーザーがストップまたはキャンセルを明示的に選択するまで、計測セッションを保持する。

長時間計測が継続している場合は、画面上に注意メッセージを表示する。初期設定では12時間以上を長時間計測とする。

## 第6章 手動作業時間登録機能

### F-11 手動登録

**概要**

ユーザーが作業時間を直接入力して登録できる。

**処理**

1. 作業日を選択する。
2. 作業項目を選択する。
3. 作業時間（時間・分）を入力する。
4. 必要に応じてメモを入力する。
5. 登録ボタンをクリックする。
6. 入力内容を検証する。
7. DBに作業記録を保存する。
8. 集計エリアと履歴エリアを更新する。

**入力例**

| 項目 | 入力値 |
|---|---|
| 作業日 | 2026/10/29 |
| グループ | 案件A |
| 作業項目 | 詳細設計 |
| 時間 | 1 |
| 分 | 30 |
| メモ | 画面設計書の修正 |

登録される作業時間は1時間30分とする。

### F-12 入力チェック

1. 作業日は必須とする。
2. 作業項目は必須とする。
3. 時間・分は0以上の整数のみ入力可能とする。
4. 分は0〜59とする。
5. 合計時間が0分の場合は登録不可とする。
6. 1件の登録上限は24時間とする。
7. 存在しない作業項目IDはエラーとする。
8. アーカイブ済み作業項目への新規登録は禁止する。
9. 入力エラーは画面に表示する。

### F-13 手動登録データの扱い

1. 手動登録した時間もストップウォッチで計測した時間と同様に集計する。
2. 記録方法をMANUALとして保存する。
3. 手動登録した作業記録には開始・終了日時を設定しない。
4. 作業日は別カラムに保存する。
5. 手動登録した作業時間は指定した作業日のみに計上する。

## 第7章 作業時間保存・履歴管理機能

### F-14 作業時間保存

1. 作業時間はPostgreSQLに保存する。
2. ストップウォッチでの記録方法はTIMERとする。
3. 手動登録した記録方法はMANUALとする。
4. 1回のストップ操作または手動登録操作につき1件の作業記録を作成する。
5. 同じ作業項目に対して複数件の記録を登録できる。
6. データ保存に失敗した場合は、保存成功と表示しない。
7. 同一の停止操作が重複送信されても記録を二重作成しない。

### F-15 作業記録履歴

1. 指定日の作業記録を一覧表示する。
2. ストップウォッチ記録と手動登録記録を区別して表示する。
3. 各記録の作業項目名・グループ名・作業時間を表示する。
4. ストップウォッチ記録は開始・終了時刻を表示する。
5. 手動登録記録は登録した作業日とメモを表示する。

### F-16 作業記録編集

1. 保存済みの作業記録を編集できる。
2. ストップウォッチ記録は開始日時・終了日時を編集できる。
3. ストップウォッチ記録の経過時間は編集後の日時から再計算する。
4. 手動登録記録は作業日・作業項目・時間・メモを編集できる。
5. 編集後の集計結果を再計算する。

### F-17 作業記録削除

1. 保存済み作業記録を削除できる。
2. 削除前に確認ダイアログを表示する。
3. 削除された記録は集計対象から除外する。
4. 削除後に画面の集計結果を更新する。

## 第8章 日別作業時間集計機能

### F-18 日別集計

指定した日付について以下を集計する。

- 作業項目別合計時間
- グループ別合計時間
- 全作業時間

集計対象は、ストップウォッチ記録と手動登録記録の両方とする。

### F-19 作業時間集計ルール

1. 同じ作業項目の複数記録は合算する。
2. ストップウォッチ記録と手動登録記録も合算する。
3. 計測中の未確定時間は集計しない。
4. キャンセルした計測時間は集計しない。
5. 日付をまたぐストップウォッチ記録は日付ごとに分割して集計する。
6. 手動記録は指定された作業日のみに計上する。
7. 集計基準タイムゾーンはAsia/Tokyoとする。
8. 内部計算にはミリ秒単位の経過時間を用いる。
9. 表示はHH:MM:SS形式とし、24時間以上の累計も表示できるようにする。

### 8.1 集計例

2026年10月29日

| グループ | 作業項目 | 計測時間 | 手動入力 | 合計 |
|---|---|---|---|---|
| 案件A | 詳細設計 | 1時間30分 | 1時間 | 2時間30分 |
| 案件A | プログラミング | 2時間 | 30分 | 2時間30分 |
| 自己学習 | AWS学習 | 45分 | 0分 | 45分 |

**グループ別集計**
- 案件A：5時間
- 自己学習：45分

**1日合計：5時間45分**

## 第10章 技術構成

### 10.1 採用技術

| 分類 | 技術 |
|---|---|
| 言語 | Java 21 |
| フレームワーク | Spring Boot 3.x |
| 画面 | Thymeleaf |
| フロントエンド | HTML / CSS / JavaScript |
| API通信 | Fetch API |
| データベース | PostgreSQL |
| DBアクセス | Spring JDBC（JdbcTemplate） |
| ビルド | Maven |
| テスト | JUnit 5 / Mockito |
| バージョン管理 | Git |

Spring Data JPA、Hibernateは使用しない。

### 10.2 アーキテクチャ

以下の3層構成を採用する。

**Controller層**
- 画面表示
- HTTPリクエスト受付
- パラメータチェック
- HTTPレスポンス返却

**Service層**
- 作業時間計算
- 計測セッション管理
- 作業項目管理
- 作業時間集計
- トランザクション管理

**DAO層**
- SQL実行
- データ登録・取得・更新・削除
- PostgreSQLとの通信

Controllerから直接DAOを呼び出さない。

### 10.3 フロントエンド・バックエンド連携

- Thymeleafで初期HTMLを生成する。
- JavaScriptで画面操作を制御する。
- Fetch APIを使用してSpring Bootと非同期通信する。
- JSON形式でAPIリクエスト・レスポンスを送受信する。
- ストップウォッチの経過時間はJavaScriptで表示する。
- 作業時間の確定値はSpring Boot側で計算する。

## 第11章 API要件

### 11.1 グループ管理API

| メソッド | URL | 処理 |
|---|---|---|
| GET | /api/groups | 一覧取得 |
| POST | /api/groups | 登録 |
| PUT | /api/groups/{id} | 更新 |
| DELETE | /api/groups/{id} | 削除 |

### 11.2 作業項目管理API

| メソッド | URL | 処理 |
|---|---|---|
| GET | /api/work-items | 一覧取得 |
| POST | /api/work-items | 登録 |
| PUT | /api/work-items/{id} | 更新 |
| PATCH | /api/work-items/{id}/archive | アーカイブ |

### 11.3 ストップウォッチAPI

| メソッド | URL | 処理 |
|---|---|---|
| POST | /api/timer/start | 計測開始 |
| POST | /api/timer/stop | 計測停止・保存 |
| POST | /api/timer/cancel | 計測キャンセル |
| GET | /api/timer/status | 計測状態取得 |

#### 計測開始API

リクエスト例：

```json
{
  "workItemId": 1
}
```

処理：
1. 作業項目の存在確認
2. 計測状態の確認
3. 計測開始日時の取得
4. 計測セッション登録
5. セッションID・開始日時を返却

#### 計測停止API

リクエスト例：

```json
{
  "sessionId": 1
}
```

処理：
1. セッションの存在・状態確認
2. 終了日時取得
3. 経過時間計算
4. 作業記録保存
5. セッション状態をSTOPPEDへ変更
6. 保存した記録を返却

記録保存と状態変更は同一トランザクションで実行する。

#### 計測キャンセルAPI

リクエスト例：

```json
{
  "sessionId": 1
}
```

処理：
1. 対象セッションを取得する。
2. セッションがRUNNINGであることを確認する。
3. セッション状態をCANCELEDに更新する。
4. 作業記録は作成しない。
5. キャンセル結果を返却する。

#### 計測状態取得API

レスポンスには以下を含める。

- 計測状態
- セッションID
- 作業項目ID
- 作業項目名
- 開始日時
- サーバー現在日時

計測中セッションが存在しない場合は未開始状態を返す。

### 11.4 手動作業時間登録API

| メソッド | URL | 処理 |
|---|---|---|
| POST | /api/work-records/manual | 手動作業記録登録 |

リクエスト例：

```json
{
  "workItemId": 1,
  "workDate": "2026-10-29",
  "hours": 1,
  "minutes": 30,
  "memo": "画面設計書修正"
}
```

処理：
1. 入力値チェック
2. 作業項目存在確認
3. 時間・分をミリ秒に変換
4. 記録方法をMANUALとしてDB保存
5. 保存結果返却

## 第12章 データベース要件

### 12.1 work_groups：作業グループ

| カラム | 型 | 内容 |
|---|---|---|
| id | BIGINT | 主キー |
| name | VARCHAR(100) | グループ名 |
| created_at | TIMESTAMPTZ | 登録日時 |
| updated_at | TIMESTAMPTZ | 更新日時 |

### 12.2 work_items：作業項目

| カラム | 型 | 内容 |
|---|---|---|
| id | BIGINT | 主キー |
| group_id | BIGINT | グループID、NULL可 |
| name | VARCHAR(200) | 作業項目名 |
| is_archived | BOOLEAN | アーカイブ状態 |
| created_at | TIMESTAMPTZ | 登録日時 |
| updated_at | TIMESTAMPTZ | 更新日時 |

### 12.3 work_records：作業記録

| カラム | 型 | 内容 |
|---|---|---|
| id | BIGINT | 主キー |
| work_item_id | BIGINT | 作業項目ID |
| record_type | VARCHAR(20) | TIMER / MANUAL |
| work_date | DATE | 作業日（手動登録時） |
| started_at | TIMESTAMPTZ | 開始日時、NULL可 |
| ended_at | TIMESTAMPTZ | 終了日時、NULL可 |
| duration_ms | BIGINT | 作業時間（ミリ秒） |
| memo | TEXT | メモ |
| created_at | TIMESTAMPTZ | 登録日時 |
| updated_at | TIMESTAMPTZ | 更新日時 |

**保存ルール**

TIMERの場合：
- record_type = TIMER
- started_at / ended_atを保存
- work_dateはNULL
- duration_msは終了日時と開始日時の差から計算

MANUALの場合：
- record_type = MANUAL
- work_dateに指定日を保存
- started_at / ended_atはNULL
- duration_msに入力された時間を保存

### 12.4 timer_sessions：計測セッション

| カラム | 型 | 内容 |
|---|---|---|
| id | BIGINT | 主キー |
| work_item_id | BIGINT | 作業項目ID |
| started_at | TIMESTAMPTZ | 計測開始日時 |
| ended_at | TIMESTAMPTZ | 終了日時、NULL可 |
| status | VARCHAR(20) | RUNNING / STOPPED / CANCELED |
| created_at | TIMESTAMPTZ | 登録日時 |
| updated_at | TIMESTAMPTZ | 更新日時 |

**制約**

- RUNNINGのセッションは同時に1件のみ。
- キャンセルされたセッションはCANCELEDとして保持する。
- CANCELEDのセッションから作業記録を生成しない。
- 停止したセッションはSTOPPEDとする。
- work_recordsにtimer_session_id（BIGINT、NULL可、一意制約）を追加し、TIMER記録と元セッションを関連付けて二重保存を防止する。

### 12.5 データベース制約

- 主キーはBIGINT自動採番。
- 外部キー制約を設定する。
- 経過時間は正の整数とする。
- duration_msには正数チェック制約を設定する。
- record_typeおよびstatusには許可値制約を設定する。
- work_itemsのgroup_id削除時はNULLにする。
- 作業項目は過去記録との参照関係を保持する。
- RUNNINGセッションが同時に複数存在しないよう、DB制約を設定する。
- TIMERレコードでは開始・終了日時、MANUALレコードでは作業日が必須となるよう制約を設定する。

### 12.6 トランザクション

以下の処理にはSpringのトランザクション管理を使用する。

- ストップウォッチ停止と作業記録保存
- 計測キャンセル
- グループ削除と作業項目更新
- 複数テーブルを更新する処理

## 第14章 非機能要件・テスト要件

### 14.1 操作性

- 作業項目の選択から計測開始まで簡単に操作できること。
- ストップウォッチの文字は大きく表示する。
- 計測中かどうかを明確に区別する。
- キャンセルボタンはストップボタンとの押し間違いを防ぐ配置にする。
- スマートフォンの画面幅にも対応する。

### 14.2 データ永続性

- データはPostgreSQLに保存する。
- 再読み込みやブラウザ再起動で保存済み記録が消えない。
- 計測中セッションもDBに保持する。
- キャンセルしたセッションは作業記録に変換しない。
- 保存失敗時はロールバックする。

### 14.3 セキュリティ

- DB接続情報は環境変数で管理する。
- SQL実行にはプレースホルダーを使用する。
- APIに対して入力値の検証を行う。
- Thymeleafでユーザー入力値を安全に表示する。
- 原則としてCSRF対策を有効にする。
- 初期バージョンではローカル環境でのみ利用し、認証なしでインターネットに公開しない。

### 14.4 単体テスト

以下を検証する。

- 作業時間計算
- 手動入力の時間変換
- 日別集計
- グループ別集計
- 日付をまたぐ時間の分配
- 入力値チェック
- ストップウォッチの状態遷移

### 14.5 結合テスト

以下を検証する。

1. 作業項目登録→計測開始→停止→保存
2. 作業項目登録→計測開始→キャンセル
3. 計測開始→再読み込み→停止
4. 計測開始→再読み込み→キャンセル
5. 手動時間登録→DB保存→集計反映
6. 同じ作業項目への複数回登録
7. ストップウォッチ記録と手動記録の合算
8. 停止APIの二重呼び出し
9. キャンセルAPIの二重呼び出し
10. キャンセル後の停止API呼び出し
11. DBエラー時のロールバック
12. 日付またぎの集計
13. 作業記録の編集・削除
14. ブラウザ再起動後の計測状態復元

## 第15章 Codexへの実装指示・受け入れ基準

### 15.1 実装方針

本要件定義書に基づいて、Java / Spring Boot / Thymeleaf / PostgreSQLを使用した作業時間記録アプリを実装すること。

**技術条件**
1. Java 21を使用する。
2. Spring Boot 3.xを使用する。
3. Thymeleafで画面を作成する。
